Verdict HOLD; Codex disagrees with Opus (who said MERGE-WITH-FIXES). Keep `drainPluginOutbox` OFF. With it ON, Manager would also pick up Civil's reports from the plugin queue and write them to the office IT folder.

1. **What would leave the PC:** machine reports, command usage (command name, result, timings, a drawing/job label) and faults (message, details). User and computer names are replaced by stable codes, which still travel with each report and in file names.
2. **"Is it a Civil record?" is decided by finding a piece of text, not by checking the whole record.** A damaged record that contains the Civil name followed by unfinished private text still goes out unchanged. A Structural record with a Civil identifier nested ahead of its own identifier would also pass.
3. **Cleaning gaps:** a drawing name without a job number keeps the client's word (`Opened <client> [drawing name removed]`); plain sentences naming a client or site are not cleaned at all; login or computer names of two letters or fewer are not replaced; unknown extra fields, list items and file names are copied as they are.
4. **It deletes things that were never sent:** Structural records, records with no identifier, oversized or unreadable ones, old files before the first "ON" time, and support bundles. You asked for Structural records to stay on the PC.
5. **Reliability:** one locked old file can stop the whole upload; a newer report that replaces one after it was read can be deleted unsent.
6. **Codex's required fixes before it is reconsidered:** (a) read and check the whole record, require one top-level Civil identifier, and build the outgoing record from an approved field list only; (b) keep Structural, unknown and damaged records on the PC and never use a first-ON time to purge history, one bad file must not block the rest; (c) close the cleaning gaps (whole spaced drawing names, short names, no free-text diagnostics unless proven clean); (d) build outgoing file names from validated codes, and delete only the exact source file that was sent; (e) honest result wording and tests (including registering the switch name in the known-switch list).
