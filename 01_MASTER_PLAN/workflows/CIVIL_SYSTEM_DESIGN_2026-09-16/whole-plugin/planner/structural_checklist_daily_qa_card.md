## One row — select, review and make the right kind of outcome

| Step | Drafter sees / does | Proposed outcome and authority boundary |
|---|---|---|
| **1. Select one row** | Main lists row name, section, scope, source/Manual/Unknown state, status, assignee/reviewer, last decision/time and an optional link to its drawing element, calculation, schedule or markup item. Selecting shows only the chosen drawing/element evidence in a large side preview. | A selected row is a review item, not an instruction to alter a beam, calculation or drawing automatically. No nearby entity, crossing or matching label becomes linked by proximity. |
| **2. Identify the row class before acting** | The status control labels **Automatic Pass / Automatic Fail / Automatic Unknown / Manual confirmation / Assigned for review / N/A**. A brief source/reason area says why the status exists. | ST9-10 is exact: a user cannot turn Automatic Fail or Automatic Unknown into Pass. Fail/Unknown remains visible and blocks ready-to-issue until resolved or formally approved by its owning workflow. This card does not invent a formal-approval action. |
| **3. Make a Manual confirmation** | For a Manual row, choose Confirm checked/approved only after reviewing the shown evidence; the confirmation pane shows user, time, row identity and any optional comment before Apply. | Apply records the manual outcome and receipt separately from a drawing save, issue handoff or engineering adoption. Cancel/Escape before Apply changes no row. A manual check is not an engineering calculation. |
| **4. Mark N/A only with its reason** | Main asks for the compulsory reason and shows row, current scope and proposed N/A result before Apply. | ST9-10 requires the reason. N/A clears neither an Automatic Fail/Unknown nor an unrelated blocked requirement. Cancel leaves the prior status and reason unchanged. |
| **5. Assign or leave a project note** | More: **Assign for review** names a reviewer and scope. **Add Project Note** opens a linked note draft with the checklist row and current drawing context shown. | ST9-11/12 note classification remains explicit: General project note, Drafting task, Engineering decision required/recorded, Site/query, Markup or Superseded. The note is not a new rule merely because it is attached; linked-note save/conflict handling remains the Notes card’s contract. |
| **6. Return to drafting** | Apply returns a receipt: row identity, intended status, user/time/reason, linked item identifiers and whether the open drawing data was changed. It keeps the selected drawing primary. | **Applied to open drawing** is distinct from **DWG saved**, **issue result**, **Built**, **Tested**, **Installed** and **Tim-accepted**. No silent QSAVE or issue publication follows a checklist action. |

## Cancel, change and reopen boundaries

| Situation | Proposed truthful result |
|---|---|
| Cancel/Escape while filtering, selecting evidence, writing N/A reason, assignment or project-note draft | No row status, assigned reviewer, note link, library or drawing data changes. The selected row may remain selected as a UI preference only. |
| A drawing/schedule/calculation/markup change arrives while a confirmation is pending | Show Before / Current / Pending row basis. Mark the pending confirmation **Needs review** where it consumes changed evidence. Do not erase a prior manual outcome, silently pass the row, or change an unrelated row. |
| Template/library changes after this drawing checklist was created | Current source does not establish a merge/revision policy. Show the drawing’s existing instance beside a candidate revision. Never silently reset completed checks; use the root22 replacement/recovery gate. |
| Current source writes to the open drawing, then the user closes without saving | It may have been applied to the open drawing; disk persistence is **Unknown** until a real save/reopen check. Do not call a checklist row “saved” merely because an in-window refresh occurred. |
| Partial/failed current storage operation | Read back the selected row and open-drawing instance before retry. Receipt distinguishes previous result retained, new result applied, partial/Unknown and no result; never repeat a change on label alone. |

## Fictitious daily drawing example

On a synthetic Level 1 framing drawing, the drafter opens `CECHECKLIST` and lands in **Coordination → QA Checklist**. A Structural row says “Verify existing wall construction” and is **Manual**; its side preview shows the selected source evidence. The drafter adds a reasoned project note classified **Engineering decision required**, then Cancels the row confirmation because a revised background arrives. The draft note and unconfirmed row stay separate.

A second row is **Automatic Unknown — B4 calculation link stale**. The drafter cannot tick it to Pass; they use **Assign for review** and return to the drawing. A third row is irrelevant, so they enter an N/A reason and Apply. The receipt names that one row and open-drawing state, not an issue result. They reopen the panel, read the current checklist instance and then save/reopen the synthetic DWG in a future native check. No template revision, note, timer entry or engineering basis moves to another drawing.
