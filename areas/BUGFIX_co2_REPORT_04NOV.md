# BUGFIX co2 report: CIVIL-OFF-2, the question when an older drawing opens (Wed 4 Nov 2026)

## FOR TIM

1. **What you will see (once it is installed, which it is not):** open a drawing that has a CE record and no CE version stamp, which means every drawing saved before this build, or one stamped before 3.0.89. A box asks once: "This is an older project. Upgrade it now, or leave it as it is (Civil OFF)?" Nothing in the drawing has changed at that point.
2. **Press No, press Escape, or close the box:** the drawing is tagged Civil OFF (slice 1) and one line says nothing was changed. This is the default answer. It stays OFF for a colleague too, because the tag is inside the drawing.
3. **Press Yes:** the pipe upgrade runs as it does today, with its PRE_C7 backup, and the drawing is then stamped with this CE version. Only then is the question never asked again for that drawing.
4. **Never asked:** a drawing already OFF, a drawing with no CE record (a Structural drawing), or one stamped 3.0.89 or later.
5. **On AutoCAD 2022 to 2024:** if someone presses Yes, one line says "Open this drawing in AutoCAD 2027 to upgrade it." Nothing is written and CE asks again next time.
6. **My own mistakes first:**
   1. I first built "stamp the drawing every time CE saves it". The safety test for Undo and Redo (the BUG-861 rule) failed, because that write could happen between commands. I took it out. I did not change the test to make it pass. Cost: a new drawing CE starts a record in after this build has no stamp, so it gets asked once on its next open. That is a real nuisance until the stamp-on-save is built and reviewed by Opus.
   2. My "before" listing of your real AppData folders was cut short by my own command (it kept 4 files, the real count is about 37,000), so I cannot give a true before-and-after comparison. What I can say is below in the technical part.
7. **NOT proven:** nobody has opened any of this in AutoCAD. I have not seen the box, the tag, the command-line line or the upgrade after Yes. The tests check the rules and that the code is wired in the right order, not the drawing.
8. **Robot case that should prove it (to be written, nothing exists yet):** name `CO2_older_project_ask`, in the style of N31_dp_time.
   1. **Setup:** a copy of the Dromana job (made by a build before 3.0.89, so no stamp), Settings left as shipped.
   2. **What it types and reads:** it opens the copy and waits for the box. It reads the box text and checks it equals "This is an older project. Upgrade it now, or leave it as it is (Civil OFF)?". It presses No. It then reads the command line for "left as it is (Civil OFF)" and reads the drawing's CE_CVL_DISCIPLINE value, which must be OFF. It then runs a Civil command and checks the line "Civil is OFF in this drawing." appears.
   3. **Second drawing:** the same copy opened again, pressing Yes. It checks the PRE_C7 backup file exists, the pipe count converted matches the open-time upgrade line, and the CE_CVL_VERSION_STAMP value reads the build number (for example 3.0.93).
   4. **Switch-off control:** set `options.askAboutOlderProjectsOnOpen` to false before launch (CE reads settings at AutoCAD start). Open the same copy: no box appears, the upgrade line appears as it does today, and CE_CVL_DISCIPLINE is not OFF. That is the broken twin.
   5. **Needs a Codex look:** the box itself (wording, default button on No).
