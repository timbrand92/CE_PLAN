1. **RD10-01 — MEDIUM — SURE — the unreadable-record hold does not follow Undo/REDO. VERIFIED-BY-READING.**

   **File:line.** At #1658 `f007893b`, `Modules/Drainage/Services/ProjectDataService.Persistence.cs:211` updates the hold only during the normal load; `:844` implements that update. History reload instead reads at `:1077` and adopts the restored data at `:1122`, without updating the hold. Its Idle retry has the same omission at `:1024` and `:1038`. The later save skips and clears the pending save at `:580` and `:582`; the memory-only gate is at `:1153`.

   **What the drafter sees.** Undo removes the change that made a CE record unreadable. CE successfully reloads the good record, but later still says it cannot save over an unreadable record. Repeating a CE action does not cure this. New drafting may appear on screen while its CE project-record update is not saved.

   **Exact failure scenario.** The current drawing has acquired the hold through a normal failed load, and an undoable change has a readable record as its preceding state. U restores that readable record. LinkService calls the history reload (`LinkService.Reactors.cs:908`, base `f7f7d551`), which replaces the project data but leaves `_unreadableRecord` held for the database pointer. Same-drawing command initialisation does not force a normal reload: `ProjectDataService.Mutations.cs:163` returns early. The next ordinary save therefore still skips. This concerns the new safeguard's history lifecycle, not the original damage or the already-known overwrite fault.

   **DETERMINISTIC TEST — fixture, NOT RUN.** In the later authorised native test lane, prepare a synthetic millimetre Civil drawing containing recognised pit P1 and a valid embedded CE record. Before that command finishes, exercise the production normal-load path for that drawing so the new hold is acquired. Do not fake the hold flag. Verify the damaged bytes and the initial “could not be read” notice. The fixture command's record change must be the most recent Undo item.

   **Typed steps and assertions.** Type `U`. Assert the exact pre-damage record bytes are restored and the CE log reports `Project data reloaded after Undo/Redo: pits=1, pipes=0`. A read-only test observation must now report the unreadable-record hold false; current source predicts true. Wait for Idle, then type `REDO`: the damaged bytes must return.
