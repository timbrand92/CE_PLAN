### #987: BUG-561, number-only Edit Pit Save keeps a detention pit's grate and solid-cover sides (head 33d4d05e)

1. **What changes for the drafter.**
   1. **Stale record (commit e54b0aa5):** when a detention pit's stored "Solid Left / 0 deg" disagrees with the block on the drawing by more than 5 degrees, Edit Pit now fills the window from the block, not the record (`PitEditCommand.cs` on the PR, `ResolveDetentionForEdit` and `DetentionRecordDisagreesWithBlock`, about lines 2012-2035). So a number-only Save asks for the angle the block already has, and the sides no longer swap. Save then writes the corrected sides back to the record (tip line 1803-1804, unchanged).
   2. **Odd angles (commit 33d4d05e, Hunt D1):** a tank at 30 degrees (Align to pipe, or ROTATE) is no longer squared to 0 on Save.    3. **Matches the carpark?** Yes for the reported case (C1 to C99, sides swapped) and for the Hunt E note ("must also test the Align to pipe at 30 degrees squared to 0 case"). The tests cover 30 degrees.

A pipe at 45 degrees is common on a real site, so this is a real case, not a corner.

My note: this changes what Save does to every detention pit, so a switch (ON) would let a colleague get the old behaviour back if the robot finds a surprise. Not required by the carpark; CE 01's call.
