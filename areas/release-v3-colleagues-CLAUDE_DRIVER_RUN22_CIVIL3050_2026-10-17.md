## D. What this run teaches the driver (for the tooling worker)

1. **CDFW cannot be cancelled by the driver.** `esc` refuses because the CDFW prompt text is not in the log while it waits. A bare `CDFW` wedges AutoCAD at 1.5 cores until `quit -Kill`. Suggestion: allow `esc` when the newest echo is a CE command with no later `Command:` line and CMDACTIVE is above 0, even with no prompt line. Until then: never type a bare CDFW. A chain with an empty line does not cancel it ("Invalid point") and places a floor waste.
2. **Window titles that are not what the guide says.** "Creative Engineering | CDCHECKDWG results" is wrong; the real title is "Creative Engineering | Check consultant drawing results (CDCHECKDWG)". Using the wrong title gave a false "prompt alarm" (AutoCAD was fine and the window was open). Real titles seen: "Creative Engineering | LandXML import", "Creative Engineering | X-Civil import", "Creative Engineering | Pit Schedule (PITSCHEDULE)", "Creative Engineering | What's New".
3. **The "What's New" window opened mid-session** (on the first CDFW of the first session) and held AutoCAD busy. Closing it with `ui close` took 22 s. It did not recur in the second session.
4. **A false alarm after CDFW and after CDCHECKDWG.** The driver raised its prompt alarm on a call that had in fact finished (CMDACTIVE 0 after CDFW; the CDCHECKDWG window was open). Reading `ui windows` or the command history settled both.
5. **Accessible names leak a code name.** In the CDCHECKDWG results list, every row's accessible name is "CE_CVL_SUITE.ViewModels.ImportReviewRow" (the same fault the driver's plain-English scan looks for). The visible text is fine. I did not run `ui scan`. Minor.
