# BUGFIX w229 report: BUG-229 duplicate Draw Order rows (build B-195, 3 Nov 2026)

## FOR TIM

1. **Result:** draft PR #2009 (Civil, base `claude/rel-20261102a`). Built and unit-tested. Nobody has opened it in AutoCAD, so BUG-229 stays OPEN. Nothing is marked fixed.
2. **What you will see differently:** open CDMANAGER > Draw Order. Each layer appears once (20TEXT, 25DIMS, 25TEXT, AGI DRAIN, ARROW, DOWN PIPES, DOWNPIPES, PITS HIDDEN and the rest used to show twice). Nothing saved and nothing drawn changes.
3. **The real cause:** the window was handed a copy of your saved layer rules. The copy was made from a blank rule list that already holds CE's 12 standard layers, and your saved rules (which hold the same 12) were added on top. So the 12 showed twice. The rules CE actually applies to a drawing were already clean; only the list in the window doubled.
4. **My own mistake to note first:** the carpark line "installed via #622" is wrong. #622 belongs to the CDDIAG entry just above BUG-229, not to this bug. The earlier fix never touched this list, which is why 3.0.80 still showed it. The BUG-229 entry has not been edited (I do not edit the carpark); CE 01 or the desk should add this correction.
5. **Switch:** Settings key `options.drawOrderListShowsEachLayerOnce`, ships ON. With it set to false before AutoCAD starts, the old doubled list returns exactly.
6. **NOT proven:** the real window in AutoCAD. I found the cause by reading the code and proved the list logic with unit tests (the switch-off test shows 24 rows, the doubled list Codex saw). Nobody has seen the window. Also not tested: Structural (not affected, this is Civil only), and any duplicates a user might already hold in a saved settings file (the saved list was already clean, so none expected).
7. **Robot case that proves it (named, not yet written or run):** `N_w229_draworder_once`. It starts a fresh drawing, types `CDMANAGER`, reads the Draw Order list rows through the driver, and checks that every layer name occurs exactly once (12 rows on a fresh install). Switch-off control `N_w229_draworder_once_off`: set `options.drawOrderListShowsEachLayerOnce` false in the settings file before launch (the setting is read at AutoCAD start), type `CDMANAGER` again, and check the count is 24 with each of the 12 names twice. Needs a Codex or robot look at the real window to count.

2. **Fault confirmed on the base, by reading:** `Modules/Drainage/Services/LayerService.cs`, `CloneLayerOrderSettings` (about line 1243 on the base): `new LayerOrderSettings { ... }` carries `Rules = DefaultManagedRules()` (`Modules/Drainage/Models/LayerOrderSettings.cs:27`, 12 layers, added 24 Sep by COLLEAGUE-DEFAULTS-02), then `clone.Rules.Add(...)` for every saved rule. `GetLayerOrderSettingsSnapshot` (line 868) returns that clone and `LayerManagerViewModel()` loads its rows from it (`LoadFromSettings`, no de-duplication).

4. **Ruled out:** the settings reader. `SettingsService.DeserializeSettings` and `DeserializeSettingsTolerant` both use `ObjectCreationHandling.Replace`, so a saved file does not append to the seed. `NormalizeLayerOrderSettings` already de-duplicates (case-insensitive, trimmed) on load and on save, and has since July. The Apply path uses the normalised settings, not the clone. The Structural lists (BUG-204) are a different code path.

The one-argument form reads `SettingsService.Current?.Options?.DrawOrderListShowsEachLayerOnce ?? true`. `Models/UserSettings.cs`: `OptionSettings.DrawOrderListShowsEachLayerOnce`, `[JsonProperty("drawOrderListShowsEachLayerOnce")]`, default true, documented "Default: on.". Not changed: `LayerManagerViewModel.BuildSettings` also seeds the 12, but it goes straight through `NormalizeLayerOrderSettings`, which de-duplicates with the later (user) rule winning, so it never shows.
