## Q-01 — inspect a drawing and review findings

**Retain:** existing Civil checks/dashboard/inspector and the shared Project QA destination. Source for shared pages was inspected in the identified44b2 owner copy; its existence is not installed/runtime proof.

**Observed interface:** ProjectQaPage says 'Six read-only checks of the current drawing'. It offers a contributor choice, Refresh drawing, Cancel, Previous/Next finding pages, Show in drawing and Close. With no contributor, it explicitly says nothing has been checked or changed. Retain those capabilities when simplifying terminology and layout.

The inspected shared contract names six categories: **Data, Engineering design, Plan presentation, Details/notes, Schedules, Issue readiness**. Per-category results are Pass / Advisory / Fail / Unknown. Reading state separately distinguishes Not checked / Cached / Checking / Needs attention / Ready / Unavailable. Do not collapse a cached reading, an absent contributor or an unfinished scan into a current pass.

**Journey:** open the page → see current scope and last evidence → explicitly refresh when needed → choose finding → highlight/show the correct drawing item → inspect its evidence and suggested action → return to drafting or its specific editor. Finding navigation must revalidate the target/drawing; an old ID must not jump to a nearby replacement object.

**Scope:** the existing current-drawing page is not a completed all-project/issue-set checker. Aggregating multiple DWGs needs exact per-drawing scope/currentness and the existing contributor owners. A Civil pass cannot satisfy unchecked Structural/details/sheet findings. The planned issue view retains per-sheet Unknown until its own evidence exists.

**Quiet drafting:** changed relationships and independent edits create review findings without repetitive popups. Acknowledging a finding does not erase it from history or make its engineering result pass. A user-confirmed job/item departure retains reason/source/scope and is revisited when relevant evidence changes.

**Issue:** show unresolved findings and the explicit user disposition agreed in the Structural journey. Advisory QA does not create a new arbitrary publish/drafting lockout. Mechanical validity, correct target/source identity and native protections are separate and remain enforced. Output completeness is not engineering approval.

**Scenarios:** a missing invert shows Unknown for the relevant hydraulic result; an out-of-date member schedule remains a discrepancy after Edit this only; a cancelled scan does not replace the previous reading with zero findings; switching drawings prevents a late result from appearing as current for the new drawing.

## Q-02 — repair exactly what was reviewed

**Retain:** DrawingRepairPage contributor choice, Inspect drawing, finding pages, changed/quarantined counts, Fix it, Cancel preview and Close. Existing unavailable capabilities must remain honestly labelled, not replaced with a generic 'fix everything'.

**Observed scope:** the shared page states that only repairs explicitly listed in the accepted preview can be offered, and unknown/conflicting/protected items remain unchanged. It shows unavailable placeholders for old-drawing upgrades and engineering level/geometry recovery. Those are limitations of this page/capability, not proof that a separately approved migration owner has no functionality.

**Journey:** Inspect → exact proposed repairs with before/after evidence → select the reviewed permissible scope → explicit Apply of that same current proposal → concise result. Cancel/Escape removes preview and writes nothing. An accepted local drawing repair is one Undo; save/reopen preserves corrected identities/relationships and still reports unresolved items.

**Existing shared contract:** C5 registry owns contributor/session lifecycle; discipline owns the actual repair plan, drawing validity, recheck and one-Undo behaviour. A cancelled, replaced, unavailable or already-used plan cannot be applied again. Metadata discovery does not inspect or modify a drawing. Reuse that separation; Manager must not become a second repair engine.

**No engineering inference:** recovering an exact stored link is different from choosing a nearby connection, inventing an invert or rebuilding a member from appearance. Source-specific actions require their established evidence and explicit reviewed scope. Crossing alone does not establish a hydraulic connection.

**Scenarios:** accept repair for one identified link while another is ambiguous; only the exact reviewed link changes. Edit the target after preview; Apply asks for a fresh review and does not apply the stale plan. A locked/Xref object stays protected. Repeat Apply on the completed preview; it cannot repeat a mutation.

## Q-04 — diagnostics versus design checking

Keep installation/command availability, file/log diagnostics, numerical design checks, drawing presentation checks and issue-set completeness visibly distinct. They can share navigation but not a misleading single green badge. A plugin loading successfully says nothing about drainage capacity; an intact PDF says nothing about member adequacy; a catalogue thumbnail says nothing about detail suitability.
