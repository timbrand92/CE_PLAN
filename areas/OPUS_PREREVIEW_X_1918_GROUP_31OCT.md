### #1931 B-105 BUG-613: moving only part of an RC beam or column detail prints a warning

1. **What the drafter sees:** RCBEAM and RCRECTCOL tag every piece they draw with one detail id, with the outline marked OUTLINE and the rest PART (`SectionDetailCommands.cs` 152; `ColumnDetailCommands.cs` 80; `RcDetailMoveWarningService.cs` 273 onwards). After MOVE (typed, or the grip move), if some but not all pieces of a detail moved, one command-line line says so and ends "Press U to undo, then MOVE the outline and its parts together." The move stands. This matches decision 158 ("warning for now").
2. **FAULT B (fix before install): copies share the tag, so a whole-detail move warns falsely.** COPY, MIRROR, ARRAY, COPYCLIP/PASTECLIP and COPYBASE all copy the hidden tag (XData), so the copy has the *same* detail id as the original. After a MOVE, the check gathers every piece with that id in the space (`RcDetailMoveWarningService.cs` 208-219). So moving the whole copy (or the whole original) finds the other one's pieces unmoved and prints "only N of 2N parts moved ... Press U to undo". Copying a beam section to make the next one is everyday drafting, so this fires constantly. It also tells the drafter to undo a correct move. No test covers copies.
   **Minimal fix:** if a detail id has more than one OUTLINE in the same space, it has been copied, so say nothing for that id (or warn only when the moved pieces include exactly one of the outlines and some of its own parts). Add a policy test with two outlines sharing one id. The full answer belongs to ST-08 grouping.
3. **Performance note:** after every MOVE that touches a tagged piece, the check opens *every* object in model space to read its tag (`RcDetailMoveWarningService.cs` 187-221). On a large GA that can be a noticeable pause after each such move. Storing the pieces' handles on the outline, or scanning only near the moved pieces, would avoid it. Not a blocker; measure it in the robot run.
4. **Switch:** `RcDetail.WarnWhenOnlyPartMoves` ships ON (new class at the end of `UserSettings.cs`, "Default: on."), pinned through both reads (`SwitchShipsOn_ThroughBothStartUpReads_AndOffIsKept`). With it OFF nothing is tagged and nothing is said (`TagScope.Begin`, `Apply` and `OnCommandWillStart` all check it). The command watchers are still attached at start-up with OFF, but they do nothing.
5. **Start-up hook placed to dodge a pinned test:** the watch starts from `AdminTelemetryService.Initialize` (`AdminTelemetryService.cs` 116) "not in Plugin.cs, whose hash is pinned by a test". That pin exists so start-up changes are seen; this is a start-up change kept out of its view. Two consequences:
   - **The watch can silently fail to start:** if telemetry set-up throws earlier (102-115, for example a folder that cannot be created), the move watch never starts, and nobody is told.
   - **The train class becomes FULL:** under QUESTIONS 89 a start-up change is FULL until Tim answers.
   Better: wrap the call in its own try and log it, and say in the REGRESSION_LOG that start-up changed.
6. **No hard blocks:** none; it is a warning line only. **Native protection:** MOVE leaves locked-layer pieces behind as AutoCAD always does. The warning then says the rest did not move, which is true and helpful. Tags are written only on brand-new pieces, inside the placing command's own transaction and Undo mark. **REDO:** the watcher only reads (an open-close transaction committed with no change) and writes to the command line at command end. It runs only during MOVE, which itself ends REDO anyway. There is a new registered application name, `CE_STRUC_RCDET`, in each drawing; that is normal. `RedoSafeCallGraph` passed per the author.
7. **Tests:** 23 policy tests (pure), the switch, and source guards. These are real but cover no copy case, no STRETCH, and no grip-stretch of the outline. STRETCH of a detail leaves parts behind exactly like a part-move but is not watched; ROTATE, COPY and ERASE are listed as not covered.
8. **NOT proven:** everything in AutoCAD; that `GRIP_MOVE` is the global name AutoCAD really reports; the pause on a big drawing; that one U after the warning undoes the move.
9. **Robot (x6 report case, plus NEW):** NEW case `S105_copy_then_move`: RCBEAM, then COPY the whole detail 2000 to the right, then MOVE the whole copy. Expect NO warning (it fails today; fault B). NEW: MIRROR then MOVE, same expectation. NEW: time the MOVE on the largest Structural test drawing with one tagged detail.
