# CODEX REVIEW — PR #2005 / B-186 / BUG-1046 — 3 November 2026

1. **Verdict: FIX FIRST.** The original Design Check dashboard finding was valid, but has been corrected in the current head. A different drawing-safety defect remains: the label-style editor can now reach its drawing-writing action during REFEDIT. Review completed 3 November 2026, Melbourne time.

2. **Exact blocking line — P1:** `Modules/Drainage/Services/DrawingSafetyService.cs:63` includes `CDLABELSTYLE` in `OpenAnywhereCommands`; line 94 therefore skips its REFEDIT refusal. The premise at line 61 that these commands draw nothing is false for the complete label-style workflow.

3. **Evidence and consequence:** `Modules/Drainage/Dialogs/LabelStyleDialog.xaml:134` exposes **Apply to drawing**, enabled whenever a style is selected. `Modules/Drainage/ViewModels/LabelStyleDialogViewModel.cs:199-216` saves the style and calls `LabelStyleService.ApplyAllToDrawing(doc.Database)` without a fresh REFEDIT or paper-space check. `Modules/Drainage/Services/LabelStyleService.cs:233-240` opens matching MText for write, replaces its contents and commits. Previously REFEDIT stopped CDLABELSTYLE before this action was accessible. With this PR it is reachable while a reference is being edited. For example, open the style editor during REFEDIT and apply a changed pit-label template: the writer is allowed to attempt label changes instead of refusing. This is a proven source-level protection gap; an actual Xref modification was NOT reproduced in AutoCAD.

4. **Required correction:** keep opening the office editor separate from applying changes to the drawing. Add a non-exempt protection check at the Apply action, before saving/applying, so REFEDIT cannot reach the writer. Calling pre-flight with the same exempt `CDLABELSTYLE` name would not fix it. Preserve the old OFF path. Add a regression test that proves Apply cannot call the label writer while REFEDIT is active. The existing test at `Modules/Drainage.Tests/Services/Bug1046OfficeEditorsOpenAnywhereTests.cs:25` proves only that the command is exempt; it never exercises Apply. `REGRESSION_LOG.md:9` incorrectly claims there is no drawing write.
