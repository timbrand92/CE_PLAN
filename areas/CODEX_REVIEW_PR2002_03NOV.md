1. **P1 — OFF does not restore the old pipe-label behaviour.** `Modules/Drainage/Services/LinkService.PipeAttachmentActions.cs:343-345` and `Modules/Drainage/Services/LinkService.cs:1172-1173` write the new CE-move mark into the existing, undifferentiated `PlacedByHand` field. Turning `CeMovesMarkHandPlaced` off stops further marks but does not change the reader: `LinkService.TextClashTidyUp.cs:301,313,345` checks only `HandPlacedLabelsStay`. `LinkService.SegmentAnalysis.cs:278` carries the mark forward. Reproduce: enable both switches, Slide a pipe description into a clash, turn only `ceMovesMarkHandPlaced` OFF, then Tidy labels. It remains held as hand-placed; before this fix that CE move did not mark it. The pit reader DOES check the new switch (`LinkService.TidyPitText.cs:102-103`), so pipe and pit rollback differ. Required: retain the distinction between existing/native hand marks and CE-created marks and gate the latter at read time, without discarding genuine native marks. Add an ON -> move -> OFF test, including save/reopen and a pre-existing native hand mark. Do not solve this by disabling all hand-placement protection.
2. **P2 — A no-op annotation action marks an unmoved label.** `Modules/Drainage/Commands/AnnotationEditCommand.cs:197-199` returns true after every successful TransformBy, including the identity transform from same-point Move (`129-130`) or a zero-angle Rotate (`155`). Line 102 forwards this true result and `LinkService.cs:1173` marks the label. Reproduce with an unmarked label already overlapping another: CDANNOTATIONEDIT, Move, choose the same base and destination point; Tidy now refuses to move it. Required: return false for no meaningful change, with regression cases for zero translation, zero/full-turn rotation, cancellation and a real move. The existing grip action already has a meaningful-position guard (`LinkService.PipeAttachmentActions.cs:273-285`); the annotation path does not.
3. **P2 — CDANNOTATIONEDIT still misses pit cover text.** `Modules/Drainage/Commands/AnnotationEditCommand.cs:102` sends every annotation to the pipe-only updater. `LinkService.cs:1127-1154` reads a pipe attachment owner and requires a Polyline; a pit cover text uses the separate `PitAttachmentKey` (`LinkService.Persistence.cs:634-647`). It exits before marking. The new `CoverTextPlacedByHand` writer is only in `LinkService.PitCoverText.cs:163-166`, reached with marking enabled by CDPITCOVERFLIP. Reproduce: enable hand-placed labels, the new switch and pit-text tidy; move a pit cover text into a clash with CDANNOTATIONEDIT; Tidy still moves it. This is a CE-command gap, distinct from the explicitly excluded native MOVE / BUG-1252 case. Required: route successful pit-cover annotation moves through the pit mark in the same command's safe persistence path and test both command and grip routes, with OFF and Cancel controls.
4. **P2 — Existing locked-layer regression test is broken by this PR.** `Modules/Drainage/Commands/AnnotationEditCommand.cs:186` changes ApplyTransform from void to bool, but `Modules/Drainage.Tests/Rules/Bug284LockedLayerChangeTests.cs:268` still slices the source using `private static void ApplyTransform(`. The independent full suite fails `SourceGuard_CdAnnotationEdit_RefusesALockedLabel_BeforeAskingForPoints` because the marker index is -1. This failure is directly attributable to the changed signature, not an assumed baseline failure. Required: update the test marker while retaining both the pre-prompt lock check and the protected write assertions, then rerun the suite.
5. **Test weakness explaining the misses:** `Modules/Drainage.Tests/Rules/Bug879CeMovesMarkHandPlacedTests.cs:106-123` checks source substrings, not the resulting label state. The Cancel claim only checks that the file contains `return false;`. These tests cannot catch the three paths above. Default-read tests are useful and are separately assessed below.
