# BUGFIX x6 report: B-105, BUG-613, moving an RC beam warns (Structural), Sat 31 Oct 2026

## FOR TIM

1. **Draft PR #1931 (B-105)**, against the Structural line `claude/rel-20261026s`. Built and unit-tested only. Nobody has opened it in AutoCAD. BUG-613 is not marked fixed.
2. **The fault was still there** on the installed Structural line (1.0.125, head 204dfad2). Nothing tied the pieces of an RC beam together: only the outline carried a tag, and the bars, ligature, labels and dimensions carried nothing. So there was no warning to find.
3. **What you will see:** place an RCBEAM or RCRECTCOL, then MOVE only the outline. The command line prints one plain line, for example: "RC beam detail: only the outline moved. Its bars, ligature, labels and dimensions (8 parts) did not move. Press U to undo, then MOVE the outline and its parts together." Move only the bars and labels without the outline and it says the outline did not move. Move the whole detail and it prints nothing. The move always stands; nothing is blocked.
4. **Switch (ON):** Settings, RcDetail.WarnWhenOnlyPartMoves. Turned OFF, CE tags nothing and says nothing, so the drawing is exactly as before.
5. **Limits you should know:** a beam or column placed by an older build has no tags, so it gives no warning. The round column (RCCIRCCOL) is not covered. ROTATE, COPY and ERASE are not watched. Full grouping (card ST-08) is not built.
6. **My own mistakes:** (a) I first put the start-up line in Plugin.cs, then found a test pins a fingerprint of that file, so I moved it to AdminTelemetryService.Initialize. (b) The first build failed because the test project needs the main project restored in its "Hosted" flavour; I restored it by hand. (c) I used one bare python line to edit a message string; it did no harm.
7. **Robot steps for CE 02 (exact AutoCAD steps):**
   1. Open a copy of a blank metric drawing at DIMSCALE 20. Type RCBEAM, choose Plain, 300 x 500, 40 cover, 3N16 bottom, 2N12 top, N10 ties, Place, pick a point.
   2. Type MOVE, click the outline only (press Enter), pick a base point and a second point. Expect the command line to show the "only the outline moved ... (8 parts)" line (parts count may differ with the bar layout). The bars stay behind, as before. Press U: the outline returns.
   3. Type MOVE, window-select the whole beam (outline and all parts), Enter, base point, second point. Expect no RC warning line.
   4. Type MOVE, click one bar only. Expect "only 1 of N parts moved" style line (a lone part with the outline staying gives the "moved but the outline did not" wording only when exactly the outline stayed).
   5. Switch control: set RcDetail.WarnWhenOnlyPartMoves to false in a copy of the settings, place a new RCBEAM, repeat step 2. Expect no warning line, and the beam has no CE_STRUC_RCDET tag.
8. **Robot case name:** `STR_rc_move_partial_warn` (control `STR_rc_move_partial_warn_off`). It types RCBEAM then MOVE on the outline only and checks that the command-line history contains "RC beam detail: only the outline moved" and that it does NOT appear after the whole-set MOVE. The OFF control checks the same MOVE gives no such line.
9. **Not proven:** the grip move (drag a grip, then move) is covered by the command name GRIP_MOVE, which I could not confirm without AutoCAD. Associative hatch behaviour when the XData is written was not seen in AutoCAD.
