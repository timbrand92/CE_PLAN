## Bounded blank-job conclusion

Within the two inspected files only—[`CeTextCommands.cs`](<C:/Lisp Files/CE_ACAD_PLUGIN/Modules/Structural/Commands/CeTextCommands.cs:79>) and [`FoundationService.cs`](<C:/Lisp Files/CE_ACAD_PLUGIN/Modules/Structural/Services/FoundationService.cs:628>)—there is **no declared or dispatched first raft-perimeter creation route**. The dispatch contains `FST`, child creation, `FADOPT`, regeneration/edit/delete/export; its named raft-system helper registers a host only after `FADOPT` selection or child host resolution ([`GetOrCreateRaftSystem`](<C:/Lisp Files/CE_ACAD_PLUGIN/Modules/Structural/Services/FoundationService.cs:2825>)). This is a bounded absence in those files, not a claim about the whole plugin.

**Open proposed doorway, separate from `FADOPT`:** a blank Structural drawing needs an owner-reviewed way to establish a first raft perimeter before it can enter the approved host-bound child path. It must show planned geometry/source/Manual/Unknown state, local drawing/view/level and Cancel before output; the command/gesture, geometry authority and record-creation behavior remain **Proposed/owner decision**. An externally supplied perimeter is only input evidence for `FADOPT`; it does not make the blank-job entry complete.
## Existing legacy-adoption entry — `FADOPT` stays separate

`FADOPT` remains a familiar direct legacy-adoption command/prompt. It is **not** the proposed first-host registration doorway below. Its candidate review uses transient drawing preview or the existing Foundation workspace when it is already open; it does **not** introduce a compulsory setup window.

| Step | Drafter action and shown state | Proposed result and protection |
|---|---|---|
| **1. Identify legacy raft work deliberately** | Use `FADOPT` only where existing legacy raft geometry is deliberately being reviewed. Before selection, show the active drawing/layout/view/level and state that a local host perimeter must be selected next. | Do not portray this as the blank-job start. The separate Proposed doorway below owns creation/registration of a first host. Xref, REFEDIT, locked and unsupported geometry stays protected. |
| **2. Start `FADOPT` → Raft** | Use the retained alias and choose Raft. Select the exact local candidate perimeter. A nearby hatch, label, or child line is not a host. |
| **3. Review legacy host and candidates** | Display **Before / Current / Pending** for the selected legacy host plus every discovered legacy candidate. Show no candidate as adopted yet. | Actions: **Review legacy candidates**, **Accept selected legacy candidates**, **Leave unadopted / Needs review**, **Park**, **Cancel/Escape**. **Confirm host registration** belongs only to the separate Proposed blank-job doorway below; it is not an `FADOPT` action. |

## Proposed blank-job host-establishment doorway — separate and open

This is a **Proposed** Foundation-owner interface, not a found command, built feature, approved alias or permission to change a drawing. It closes the planning gap identified above so it can be reviewed later. It may be offered from the existing Foundation owner surface or an owner-chosen direct discovery route; the exact command/gesture remains open. It is not `FADOPT` and it does not replace legacy adoption.

| Step | Proposed native-first action | Required visible boundary |
|---|---|---|
| **1. Start host establishment** | Choose **Draw raft boundary** or **Select existing local closed outline**. The drawing prompt/transient preview names the working drawing/layout/view/level and asks which path is intended; it is not a compulsory wizard. | No new alias is asserted. No Civil slab is offered as a surrogate. A protected/Xref/REFEDIT/unsupported object cannot be selected or altered. |
| **2A. Draw boundary** | Use familiar native drawing gestures to place the intended local outline. Before it is accepted as a host candidate, display its provisional identity, Manual extent, closure state and the user’s chosen local points. | The proposal does not supply an engineering perimeter, level, size or extent. Completing native drawing geometry alone creates no Foundation host record, child relationship, source adoption or layer change. |
| **2B. Select existing outline** | Select one exact local outline. Show its stable identity, current geometry, source/manual extent, drawing/layout/view/level and whether it is an existing candidate rather than a registered host. | Selection does not promote an enclosing edge, nearby hatch/text or any drawing object into a host. Drawing selection alone creates no record or child relationship. |
| **3. Inspect eligibility before registration** | Show local/protected status, closure, self-intersection result, drawing-unit state, geometry extent, source/Manual state and every Foundation-owner-required known value. Each unavailable value is shown as **Required Unknown**; the proposal does not decide a value list, units or scale. | Invalid, open, self-intersecting, protected or required-Unknown input stays **Pending**. It cannot silently close/rewrite geometry, change a layer, invent a unit/level/value, or register a host merely because an outline is visible. |
| **4. Preview candidate versus registration** | Display **Before / Current / Pending**: outline only; selected/drawn eligible candidate; and proposed registered host identity. Make the no-child scope obvious. | Actions: **Correct outline**, **Keep as standalone geometry**, **Park**, **Cancel**, and **Confirm host registration** *(Proposed)* only when the displayed eligibility/required values are satisfied. Confirming registration is separate from confirming native geometry. |
| **5. Confirm one host registration** | A separate confirmation names the exact candidate identity, source/Manual extent, local drawing/view/level and no-child initial scope. | This proposed receipt records host identity separately from boundary geometry. It does not run FADOPT, scan a draft layer, regenerate graphics, assign a type/size/depth, or create `REB`/`RIB`/`THC` children. |
| **6. Choose the next deliberate route** | After host registration, choose **Place new host-bound child** (governed by the child card) or **Review legacy candidates with FADOPT** (governed by the distinct adoption flow). | A child still needs its own selected host, driver and governing input review. `FADOPT` cannot be used as an invisible registration shortcut or as a reason to accept all legacy candidates. |

### Candidate, drawing and registration are three separate states

| Event | Proposed outcome |
|---|---|
| Escape while native boundary is still pending | No new boundary or host record is created by the cancelled gesture. |
| A native boundary was already accepted, then registration is cancelled | Retain the local standalone boundary as the user drew it, but show it as **Unregistered candidate**. Cancel does not erase it, attach a host record, alter its layer or create a child; native Undo remains a separate later proof. |
| Source/manual extent changes while candidate registration is open | Preserve the changed geometry and show Before/Current/Pending. The registration draft becomes Needs review; it can be corrected, Parked or Cancelled. No existing child is silently moved to the changed outline. |
| Registration or later child output is partial | Read boundary geometry, host record, each child link, graphics, labels/provenance and source/manual extent separately before retry. Retry needs verified absence or safe resume; it never redraws or re-registers a possibly completed part. |
| Save/reopen | Future AutoCAD evidence must separately prove local outline geometry, its candidate/registered state, host identity, source/Manual extent, required-value state and child links. Visible closed geometry alone is not proof of registration. |
## Cancel, manual, revision and reopen

| Situation | Proposed truthful outcome |
|---|---|
| Cancel/Escape before confirmation | The current selected candidate and legacy list remain only review evidence. No host record, child link, generated outline, label adoption or drawing conversion is created by the proposed target. Current source boundaries need AutoCAD proof. |
| Current direct source is invoked | Do not promise preview-only behavior or rollback: source observation shows direct candidate scanning/adoption and regeneration after selection. Inspect actual host, child, graphics and registry state before any recovery; this card does not claim it is fixed. |
| Selected perimeter/source changes during a draft | Show old/current/pending host identity and perimeter state. Park, discard or cancel the unconfirmed draft. A changed/missing perimeter places the host and its known children in **Needs review**; it does not reassign a child to another enclosing perimeter. |
| Manual positions and source choices | Preserve authored/manual child-label positions and confirmed source selections. A saved default alone changes no existing host/child. A confirmed manual position change only stales a pending presentation draft that consumed its old position. |
| Partial action / retry | Report host record, each accepted child record, graphics, labels/provenance and parked/skipped items separately as Complete/Partial/Absent/Unknown. Retry needs verified absence or a safe resume boundary; it never repeats a possibly adopted child or regenerates unrelated systems. |
| Save/reopen | Future AutoCAD evidence must read host identity/perimeter, child-to-host links, child driver/graphics/labels, source/Manual status and parked candidate evidence separately. Visible perimeter graphics do not prove a registered host. |

## Fictional blank-to-host example

A synthetic Level 1 legacy drawing contains one existing local closed raft perimeter, one local internal line and an ambiguous nearby text note. The drafter starts `FADOPT`, chooses Raft and explicitly selects the perimeter. The proposed review lists the line and note as unadopted candidates. They accept only the line after review and leave the note unadopted/Needs review; this is bounded legacy adoption, not blank-job registration. Separately, a blank-job drafter uses the **Proposed** doorway below to draw/select an eligible outline and explicitly confirms host registration before starting `RIB`. If a required depth is still Unknown, the child shows **Cannot confirm complete compound** and is Parked; it is not drawn from invented geometry. After a later supplied/reviewed input, the ordinary child-preview sequence resumes.

On reopening the host review, the line can be reviewed as one candidate and the text can remain unadopted/Needs review. Deleting or changing the source perimeter later leaves the retained host/child evidence visible for review; it does not choose the next enclosing perimeter. No numeric value, type, label or child is inferred in this example.
