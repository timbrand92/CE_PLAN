## Fictitious job state and visible identity

The synthetic job has **Level 1 plan**, **Level 2 plan** and a **section/detail view**. An attached, protected background is **Source A**; a later evidence page, **Source B**, differs on one opening. A local drawn beam and a local support are editable. A manual level mark and a manually positioned beam label already exist. One imported schedule row is pending review; one Note draft is parked under this job. No part of the scenario establishes a design value, member capacity, load path, or calculation result.

Every selected thing carries a visible **drawing / layout or view / level / stable identity**. A matching visible mark in another level is a different candidate until the user deliberately selects it. The job header comes from the shared context: an already recognised drawing uses its known context; only an unknown or ambiguous drawing is Unassigned. Pending note/time work retains its own origin and does not change the job record.

## Cross-card contradiction resolution

| Stress condition | Resolution that applies across cards | Planning status |
|---|---|---|
| **Manual section/detail creation versus linked member** | Manual creation stays available. It is Manual/Unknown and creates no fake member relation. A later relation uses an explicit reviewed binding that names both identities and their view/level. | Clarifies W6 interaction intent; no new engineering decision. |
| **Copied element versus copied detail** | Beam-only COPY produces fresh beam + label with unconnected supports and no copied detail. Detail COPY asks same-member/new-member/independent-detail. Copying one cannot silently copy, delete or rebind the other. | Reconciles W3 and W6; keeps ST-01/ST-08 decisions. |
| **Original edited while a preview is open** | The preview identifies original identity/source/revision. Any material drawing/source change makes the proposal stale and returns it to review; no delayed Apply overwrites the newer state. Pre-Apply Cancel makes no proposed change. | Same stale-plan rule as W9; target proposal awaiting implementation evidence. |
| **Same visible mark on different level/view** | Selection and every affected list show drawing/view/level/stable identity. Matching text is insufficient to batch, link, repair, copy or schedule it. | Clarifies W3/W4/W7/W8 selection boundary; native identity readback remains future evidence. |
| **Protected content appears mid-batch** | Mark item Blocked/protected, retain it unchanged, continue only with independently eligible local scope where allowed, and report Partial/blocked status. No unlock/detach/clone-around or blind retry. | Applies native-protection rule and W5/W7/W11 receipts; runtime behavior untested. |
| **Saved defaults after old manual positioning** | Saved placement settings are future defaults. Existing manual position/choice remains visible, preserved and potentially Needs review; it is never quietly reset to a saved default. | Clarifies W2/W3/W7 lifecycle; proof on save/reopen remains future. |
| **Pending note/time work after context switch** | Recognised second job changes current shared context automatically. Pending first-job Note/time draft offers Resume original unchanged, Park, Discard or Cancel; deliberate re-context is separate. | Already covered W0/W1, carried into this scenario to prevent cross-card transfer. |

## Read-through: remaining concrete interaction proposals

These are proposed cross-card interactions exposed by the walkthrough. They do not change an approved engineering decision, force a new data store or assert native implementation.

| Interaction still needing a joined user sequence | Proposed visible sequence | Safe result |
|---|---|---|
| **A detail/schedule draft depends on an element changed by confirmed foundation regeneration** | Before the regeneration Apply, show linked pending detail and schedule drafts as downstream review items. After a per-element Complete receipt, mark only those drafts **Needs review** and show current element identity plus prior draft basis. Actions: Open draft review, Park, Discard, or Cancel. | Do not rewrite a manual detail, schedule presentation override or engineering workbook value. A Partial/Unknown regeneration receipt leaves dependent draft currentness unresolved rather than calling it updated. |
| **The original selected object changes while a multi-item operation is waiting for Apply** | The preview header retains selected identity, source/revision and operation scope. On an intervening edit, show Changed since preview and disable Apply for that object. Actions: refresh selected object, remove it from the scope, or Cancel. | Completed earlier items keep their own receipt. The changed item is not reapplied from a stale preview, and no whole-batch rollback or retry is implied. |
| **A manually positioned compound is affected by a settings/library save** | Save confirmation lists future-default scope separately from current selected drawing compounds. The review shows whether the compound has Manual/pinned presentation and whether an actual operation would alter geometry, content or only default choice. | Retain Manual/pinned presentation by default. Only a direct confirmed change can put that compound into Needs review; a saved default alone cannot reset it. |
| **A schedule draft encounters a copied member/detail identity** | Show original/copy stable identities and selected relationship state before linking an imported row. Offer Keep independent, bind selected existing identity, or Mark Unknown; show the destination drawing/view/level. | A copied label/visible mark cannot bind the row. A detail copy does not create a member; a member copy does not create a detail. |
| **Protected item appears after planning but before operation** | Revalidate each item immediately before its own proposed change; surface status as Blocked/protected and remove it from the eligible subset. Main shows completed/bypassed/pending lists; More holds a read-only exclusion reason. | Never unlock/detach/clone. If other independently eligible items complete, overall result is Partial with per-item receipt; no automatic retry of the blocked item. |

The retained/manual badge, stale-object interlock, and dependent-draft review are recommended concrete interactions for later owner review. Button labels and layout remain proposals; source/runtime/native behaviour is still unproved.
