# FOR TIM

1. **The fault is real, and I found the exact cause.** CE's own save (used only by CLEAN and FASTSAVE) asks the drawing for its file name. A new drawing made from a template, not yet saved, reports the template's file as its name. CE then saved straight into that template. AutoCAD's own QSAVE would have opened Save As instead.
2. **What you see now:** in a drawing you have never saved, CLEAN and FASTSAVE do nothing and print one line: "This drawing has never been saved, so CE did not run CLEAN and saved nothing (a save would have gone into the template file the drawing was made from). Save the drawing with a name first." Nothing is cleaned, nothing is saved, and there is nothing to undo.
3. **Normal drawings are unchanged:** once a drawing has been saved with a name, CLEAN cleans and saves as it does today.
4. **One choice for you (not urgent):** if you open a template (.dwt) on purpose to tidy it, CLEAN now refuses to do anything at all. Your rule of 4 Sep is "nothing should restrict users unless it's really serious". My suggestion: CLEAN still cleans the template but does not save it, and says so in one line, so you save it yourself with QSAVE when you mean to. The draft refuses outright today.
5. **Civil is clear:** no Civil or Manager command saves the open drawing at all on the installed build, so this fault is Structural only.

# Findings (file and line at `7a94d8e8` unless marked `8de95c34`)

## 1. Is the fault real in the installed code, and by which path

1. **Confirmed by reading, two levels deep, and matches the robot evidence** (`areas\trust-run\EVIDENCE_CLEAN_TEMPLATE.md`).
2. **The commands:** `Commands/LegacyPortCommands.cs:11-15` registers CLEAN and FASTSAVE, both calling `CleanPipelineService.Run`.
3. **The save stage (`8de95c34`):** `CleanPipelineService.cs:151-172`, the "QSave" stage calls `DrawingAutoSaveService.TrySaveNow(doc, commandName, ...)` (line 160); only if that fails does it send AutoCAD's own `_.QSAVE` (line 168). The fallback stage repeats the same pair (lines 268 and 284).
4. **The managed save (`8de95c34`):** `DrawingAutoSaveService.cs:143` gets the file name from `DrawingSafetyService.TryGetNormalProjectDrawing`, then line 198 runs `db.SaveAs(drawingPath, true, DwgVersion.Current, ...)`.
5. **Where the name comes from (unchanged file):** `DrawingSafetyService.cs:187-206` refuses only `.sv$` and `.ac$`, so a `.dwt` passes. It calls `TryGetDocumentAndPath` (`:175-176`), which uses `ResolveDrawingPath`; that prefers the database's file name (`:356-359`), read at `:373` as `doc.Database.Filename`. For a new drawing made from a template, AutoCAD reports the template's full path there, while the document is still called "Drawing1.dwg". So line 198 wrote into the template, and AutoCAD then renamed the document after it (as seen in the evidence: name became the .dwt, DWGTITLED 1).
6. **Why AutoCAD's own QSAVE never got the chance:** the managed save succeeded, so the command QSAVE (which would have opened Save As for an unnamed drawing) was never reached.

## 2. Does the fix close it, for every CE save

1. **CLEAN and FASTSAVE: closed.** `CleanPipelineService.cs:70` stops first, before the undo mark, the clean-up stages, the recovery warning and any save. The QSave stage (`:165-170`) and the fallback stage (`:280-282`) check again before both the managed save and command QSAVE. `DrawingAutoSaveService.cs:165-171` refuses inside the managed save itself, before the read-only check and before `db.SaveAs`.
2. **The decision is sound for the real case:** `DrawingSaveGuard.cs:46` stops on DWGTITLED 0 (read only when the drawing is the active one, line 82; CLEAN is a modal command, so it always is). If DWGTITLED cannot be read, line 47 still stops a drawing whose name has no folder ("Drawing1.dwg"). Two independent signals; either one is enough.
3. **Other callers of the managed save:** none. `TrySaveNow` has exactly two callers, both in `CleanPipelineService.cs` (`:172` and `:284`). The old idle-timer save (CEAUTOSAVE) has no caller since UX-STD-03.
4. **Every other place Structural writes a drawing file (grep of `.SaveAs(`, `_.QSAVE`, `acadDoc.Save`, `SendStringToExecute` with SAVE, `DxfOut`, `Wblock`):** (a) `CeSheetsSyncService.cs:899`, a closed sheet file read from the register; now also refuses a `.dwt` (`:1833-1835`). (b) `CeProjectSetupService.cs:237` and `:295`, closed copies made by `File.Copy(profile.TemplatePath, targetPath)` at `:190`, so the template itself is never written. (c) No LISP, ribbon macro or registry entry sends QSAVE (one registry description mentions it, nothing runs it).
5. **Civil and Manager on the installed Civil build `9714ffdd`:** no `Database.SaveAs`, no QSAVE sent, no COM save of a drawing. The only `SaveAs` and `Save(` hits are spreadsheets, ribbon menu files and XML. Civil's save handlers only add data while AutoCAD's own save runs. So no Civil command can write a template.
6. **Never-saved drawing made from a .dwg or a .dws:** AutoCAD's Select Template box accepts those too. Covered, because DWGTITLED is 0 whatever the source file type.
7. **Drawing started with no template:** covered (DWGTITLED 0). Installed behaviour was a managed-save failure ("drawing path unavailable") followed by AutoCAD's Save As; now CLEAN stops instead.
8. **Read-only drawing:** unchanged from installed for a named drawing (managed save skips, then command QSAVE, AutoCAD's own handling). A read-only template or never-saved drawing is stopped first.
9. **A .dwt opened on purpose:** stopped by the template check (line 48). See "Before merge" item 1.
10. **A .dws opened on purpose:** not treated as a template, so CLEAN saves into it as AutoCAD's QSAVE would. Consistent with item 1 only once that decision is made.

## 3. What the drafter sees

1. **Wording is plain** and says what to do; no codes, no bug numbers, no "DWGTITLED" (a test checks). One line on the command line, prefixed "[CLEAN]" or "[FASTSAVE]".
2. **Nothing changes on refusal:** the stop is before the undo mark, before any system variable is touched and before the first stage, so there is nothing to undo and nothing to save. There is no prompt, so Cancel and Escape do not arise.
3. **Small wording fault:** the bracket "(a save would have gone into the template file the drawing was made from)" is wrong for a drawing started with no template. See "Before merge" item 3.

## 4. One code path per behaviour

1. **Kept:** one decision, `DrawingSaveGuard.Check`, called from four points. The two stage checks are not redundant: without them a refused managed save would fall through to command QSAVE, which would save an opened `.dwt` silently.
2. **Duplicate guard test:** the new `EveryWayCeSavesADrawingFile_IsListed_SoANewOneCannotAppearUnchecked` (`DrawingSaveGuardTests.cs:136-170`) repeats the existing `Commands/NoSideEffectDrawingSaveTests.cs`, which already pins every drawing save in Structural with a wider pattern (`.SaveAs(`, `acadDoc.Save`, `TrySaveNow`, `RecordManualSave`, QSAVE sent). The new one matches only the literal `db.SaveAs(` (line 158), so `database.SaveAs(` or a QSAVE sent would pass it. See "Before merge" item 5.
3. **Civil has its own "has this drawing been saved" reader** (`Modules/Drainage/Services/LpdService.cs:282`, same DWGTITLED idea). Different module, so not a breach here; a candidate for CE_SHARED later.

## 5. Tests: are they real, and what only AutoCAD can prove

1. **Real:** every new test fails without the fix (the guard class does not exist; the order checks find nothing). The decision tests use the exact situation seen in AutoCAD (name "Drawing1.dwg", file the template).
2. **But they read code text, not behaviour:** the order tests check where lines sit in the source. They cannot show that AutoCAD reports DWGTITLED 0 and "Drawing1.dwg" for this drawing, or that the template is untouched.
3. **Existing guards still fit by reading:** `NoSideEffectDrawingSaveTests` (no new save lines; comments stripped), `CleanSavesAgainTests` (the first `"QSave"` and the RegenAll order unchanged). Not run by me.
4. **Only AutoCAD can prove (robot, scratch copies only):** (a) new drawing from a template copy, not saved, CLEAN: the line, the copy's size, date and fingerprint unchanged, no XREF or HATCH 21 layer made, nothing on the undo list. (b) The same with FASTSAVE (the robot driver refuses commands with SAVE in the name; use the automation route the evidence lane used). (c) Save As to a .dwg, then CLEAN: cleans, saves, "saved <file>" line (B-178 intact). (d) Open the template copy directly, CLEAN: the template line, copy unchanged. (e) New drawing with no template, CLEAN: the never-saved line. (f) AutoCAD 2022 to 2024 (net48) for (a) and (c) if a copy is available.

## 6. Risk to the normal saved-drawing case

1. **Low.** A named drawing has DWGTITLED 1, a full path as its name and a `.dwg` file, so `Check` returns Ok and every later step is exactly the installed code.
2. **One narrow edge:** line 47 applies the "no folder in the name" test even when DWGTITLED has been read as 1. A saved drawing whose document name is not an ordinary path (for example one opened from a web address) would be refused. I know of no such case in this office; it costs one condition to remove. See "Before merge" item 2.

# Before merge (none blocks the robot test)

1. **Decision for Tim, a template opened on purpose** (`DrawingSaveGuard.cs:48`, `CleanPipelineService.cs:70`). Today CLEAN refuses everything for a `.dwt` the drafter opened on purpose, which AutoCAD itself would save. Under R-27 ("nothing should restrict users unless it's really serious"), the suggested default is: still clean, skip the save, one line "This is a template file (.dwt). CE cleaned it but did not save it; use QSAVE if you meant to change the template." Decide `.dws` the same way at the same time.
2. **`DrawingSaveGuard.cs:47`:** use the "name has no folder" test only when DWGTITLED could not be read (`dwgTitled == -1`), so a drawing AutoCAD says is saved is never refused because of how its name is written. Add a test case `Check(1, "<non-path name>", "C:\\jobs\\house.dwg") == Ok`.
3. **`DrawingSaveGuard.cs:65`:** drop the bracket, or show it only when the save path is a template. Suggested line: "This drawing has never been saved, so CE did not run CLEAN and saved nothing. Use Save As to give it a name, then run CLEAN again."
4. **`DrawingSaveGuard.cs`, summary above `StopIfSaveUnsafe` (about line 102):** the sentence "Same stop for a read-only drawing and REFEDIT is made by the other pre-flight checks" is wrong; CLEAN has no read-only or REFEDIT pre-flight in `Run`. Remove it, or say read-only is left to the managed save and AutoCAD's QSAVE.
5. **`DrawingSaveGuardTests.cs:136-170`:** remove the new inventory test, or make it reuse the wider pattern in `NoSideEffectDrawingSaveTests`; one inventory, not two.
6. **Commit message says "NOT BUILT YET, local"**, while the PR body and the lane's 12:04 line say built and 387 tests pass. Build the robot payload from `7a94d8e8` (or the fixed head) and record its hash; amend nothing in history.
