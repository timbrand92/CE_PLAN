## FOR TIM

1. **What it is:** a new tick box in Settings, Drafting tab: "After a MOVE, CE tidies labels that land on other text, and says so on the command line". Ticked by default, so nothing changes for anyone who never opens Settings. Built and unit-tested only. Nobody has opened it in AutoCAD.
2. **One real problem:** unticking it switches off more than the MOVE tidy. It also stops CE sliding labels clear when you draw a new pipe, save Edit Pipe, change a pit size in Edit Pit, split a pipe with a source, and after STRETCH, ROTATE, SCALE, TRIM or a grip edit. Example: a drafter unticks it to quieten the MOVE messages, then draws a pipe into a pit and the start invert text now sits on the pit. The row only says "After a MOVE".
3. **Second, smaller problem:** one of its own new tests says "Tidy labels is OFF by default". On the C-77 and C-78 trains, Tidy labels is now ON by default (your 29 Oct ruling), so that test goes red the moment this joins a train. A one-line fix.
4. **The three failed tests:** none comes from this change. Two are known compiled-code checks that always fail on this kind of test build. The third is a five-second log timing check that fails when the PC is busy.
5. **Tidy labels (CDTIDYLABELS) and the hand-placed label (D13, BUG-1252):** not touched. Tidy labels runs exactly as before whether the box is ticked or not, and the "placed by hand" mark is still written.
6. **Verdict: KEEP-WITH-NOTE.** Before it joins a train, limit the switch to MOVE, STRETCH and grip-type edits (or reword the row to say everything it switches off), and fix the one test. Then it can join the train after C-78, on top of `claude/rel-20261102a`. BUG-1232 (sheet border counted as a clash) is not fixed by this.
