# BUGFIX ff2008 report, 4 Nov 2026 (fix-first for draft PR #2008, B-190, BUG-959)

## FOR TIM

1. **What a drafter will see differently:** AutoCAD on a smaller second screen (a laptop at 150%). A CE window such as Calculations V2 now opens sized to that screen's usable area, so its bottom buttons stay on the screen. Before this fix it kept the big screen's height and hung off the bottom. The Civil Hub saved on the second screen also reopens sized to that screen.
2. **What I changed:** the one finding in Opus's review of 3 Nov. Size and position now both use the one screen the window lands on (above its taskbar). The "box around all screens" is gone, so no taskbar overlap and no empty corners. The setting `options.windowsKeepSecondMonitorPosition` is unchanged and still ON by default. OFF gives the old behaviour exactly.
3. **One thing for you to look at first (a possible mistake of the run, not proven):** the isolation check found `CD_Settings.json` in `%APPDATA%\TIM_CE_CADTOOLS` changed between my before and after listings (15360 bytes at 00:55 to 15270 bytes, now stamped 4 Oct 08:22). A test run writes with the current time, and this has an old time, so it looks like another job or a restore replaced it, not my run. I cannot prove that. My tests were the Drainage window-position tests only and ran with TEMP, TMP and the log folder redirected. The telemetry folder and one Structural log also moved; AutoCAD or other jobs were running. Please have someone compare it with `CD_Settings.json.PRE_WORKSHOP_20260916_121735.bak` or ask the other running jobs.
4. **NOT proven:** nobody has opened this on two real screens. It is built and unit-tested only. BUG-959 stays OPEN. Robot case N59 needs two physical screens.
5. **Robot case that proves it (style N31_dp_time):** `N59_second_screen_fits` (needs two screens, AutoCAD on the smaller). It types `CDCALC V2` (opens Calculations V2) and reads the window's bottom edge against that screen's usable bottom: it must be at or above it. Switch-off control: set `windowsKeepSecondMonitorPosition` false before launch, repeat, and the old main-screen-height overhang returns. A one-screen PC cannot see the overhang, so Codex or Tim need the two-screen PC.
