1. **BUG-1237 (CDRENUMBER).** When no pipe leaves any pit to open ground or an outfall, CDRENUMBER now says what to draw instead of "No pit discharges outside the network". It reads: "CDRENUMBER numbers the pits from the outlet, but no pipe leaves any pit to open ground or an outfall, so it cannot tell which pit is the outlet. Letting you pick the outlet pit yourself is a bigger item and is not built.
2. **BUG-1071 (CDCHECKIGNORE and CDRULEBOOK).** On a drawing whose CE data CE holds as unreadable, CE refuses to save over it. Before, you were still told "Ignored: P1 ... Type U to take it back" or "Pit invert drop set to 50" although nothing was stored. Now you get "Not saved: the CE data in this drawing could not be read, so CE has left it exactly as it is and has not saved this." plus the plain result (the finding still shows on the Checks list; it is still ignored; the pit invert drop, council or cover override is still its old value) and "Nothing was changed", so there is no Undo to expect. It does the same for the six CDRULEBOOK saves (drop by shortcut and by Drop, council set and cleared, cover override set and removed).
3. **Both switches ship ON** (`linking.renumberNoOutletSaysWhatToDraw`, `linking.saveSkippedSaysNotSaved`). Switched off, each gives the old line back exactly.
4. **Nothing else on the drawing changes.** Nothing is written, no layer is touched, no regen or view change. A normal drawing behaves exactly as before.
5. **To check in AutoCAD (after a build is installed):** BUG-1237: two pits joined by one pipe and no pipe to open ground, run CDRENUMBER, expect the sentence above. BUG-1071: the synthetic drawing from the carpark entry (P1 on a wrong layer, `lastPitNumber` set to BROKEN; `keepUnreadableDrawingRecord`, `allowIgnoreFinding`, `useSharedResult` and `wrongLayerRows` on), CDSYNC, CDCHECKIGNORE, Ignore, pick P1, reason Other, Enter: expect the "Not saved" line and no "Ignored:" line; then CDRULEBOOK 50 and CDRULEBOOK Show: the drop must not read 50.
