# Shared settings and standards — approved requirements retained

FOR TIM

A shared detail must remain editable, a project must keep its agreed standards, and a damaged settings file must produce a recoverable warning. These are already approved requirements.

Read canonical `docs/CARDS/SH-04_SETTINGS_STANDARDS.md` and `AS-01_STANDARDS_ASSET_CATALOGUE.md`, including refinements. This supplements03/11 and corrects their omissions. Historical source states do not establish current implementation or installation.

Refinement: a project keeps its adopted rulebook version. A newer office version is a reviewable difference; adoption is explicit. Personal-file recovery is not AutoCAD Undo. Project/drawing changes and external-file recovery must state their actual boundaries.

**Corruption journey:** open settings → warning identifies affected settings scope and preserved backup → retain accessible valid information and mark unestablished values Unknown → user chooses reviewed recovery/default scope → successful save verified through owner. This is a proposed presentation of approved#12, not proof the recovery implementation exists. No automatic engineering approval by fallback defaults.

## Later detail-browser decision reconciliation

The14September Structural journey permits review-on-use of existing details and project copies, with Not yet reviewed/Approved/Needs correction/Superseded states. Keep that later reviewed doorway. It does not silently approve an entire master library or remove AS1-12's intelligent-object protections. Earlier Candidate/Working/Unknown catalogue exposure rules remain relevant to ordinary standard-command assets; exact later detail-review permission is scope-specific. A useful unreviewed detail can be inspected and evaluated without becoming an approved office standard.

## Synthetic acceptance cases

- Export settings containing a synthetic key field and client-path field: neither appears in shareable output; allowed preferences remain. Import previews allowed scope, never restores secret placeholders as real credentials.
- Open a corrupt synthetic settings file: visible warning and recoverable original, no false successful reset or approved engineering default.
- Place a dynamic detail and edit its variant after save/reopen: dynamic controls and provenance persist, master unchanged.
- Insert a standard schedule/levelmark/hatch: fields, ownership and hatch semantics persist; no routine explode.
- Select a detail with an unfilled level placeholder: visible finding and deliberate disposition required for Ready status; printing capability is not engineering acceptance.
- Adopt a library revision where a project dimension differs: compare both changes and preserve the existing project value until confirmed.

No source, settings or masters changed. These acceptance cases were not executed in AutoCAD. Independent whole-plugin audit ongoing.
