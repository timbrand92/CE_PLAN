# Job documents — from automatic discovery to confirmed design evidence

FOR TIM

Open the drawing and CE recognises the job. Select/change documents controls which evidence is loaded; it does not ask you to reconnect the project folder. A new report is reviewed before its values affect the design.

This is proposed interaction detail under the approved CDDESIGN handover, [automatic context](21_AUTOMATIC_PROJECT_CONTEXT_BOUNDARIES.md), [source adoption](23_CHANGE_ALLOCATION_AND_ISSUE_HANDOFF.md) and existing evidence/privacy authority. It adds no new provider, corpus access or engineering default. It is not built.

## First opening on an empty or partly designed job

| User sees / does | Automatic assistance | Confirmation and retained work |
|---|---|---|
| Open CDDESIGN in a recognised job | Show job/drawing context and last saved design basis immediately. Discover relevant document candidates asynchronously within that job's authorised scope. | Do not create a manifest or write a design value merely by opening. Manual drawing tools remain usable while discovery continues. |
| Review discovery status | Show Finding documents / Reviewing selected documents / Partial / Ready for review with the real scope. Survey/Background folders remain eligible evidence locations; sheet-scanning exclusions do not apply wholesale. | Partial discovery is not “no requirements found”. An unavailable folder/file is named without blocking unrelated drafting. No whole-drive or neighbouring-job scan. |
| Select/change documents | Present existing loaded documents plus newly discovered candidates, their type, stated revision/date and status. Selecting a row opens a large relevant page preview. | Loaded selection is not governing adoption. Keep existing adopted source identity visible separately. No folder-link wizard. |
| Review relevant requirement | Show extracted candidate value/text with document, page, stated revision and content/version evidence. Highlight the relevant passage where available. | Missing citation, uncertain extraction or unreadable page remains Unknown/Needs review. No invented page number, source or numerical fallback. |
| Confirm design use | Compare current adopted fact/manual value against the candidate, units/purpose and affected calculation/geometry scope. | Explicit confirmation under the existing adoption contract. Newer filename, higher confidence or later date never wins automatically. |

**Main view:** current job, current governing source summary, changed/unreadable/conflicting evidence, large page/plan preview and visible Select/change documents / Review / Keep current actions. **More:** complete document list, discovery scope/status, extraction limitations and prior revisions. An unresolved controlling requirement stays visible in Main rather than being buried in More. These are arrangement proposals, not extra compulsory tabs.

## First CDDESIGN review after drafting has started

This proposed sequence applies the same approved beginning/during/end-of-job behavior to an already populated drawing. It is not a new stage selector, an executed old-project trial or authority to repair/migrate while reviewing documents.

| Existing job condition | What the first review preserves and shows |
|---|---|
| Recognised supported CE records with confirmed/manual values | Restore their actual recorded identities, source/manual basis and review status. Opening CDDESIGN does not reset them to defaults, require wholesale reconfirmation or manufacture missing history. |
| Local geometry or loose labels without established CE authority | Show only what can be established as candidate evidence through qualified readers. A displayed invert, area or tank volume is not automatically a governing value, a network connection or an adopted object. Explicit owner-controlled adoption remains separate. |
| Existing schedule or calculation output | Retain its actual input/result identity and known currentness. A placed table or printed value cannot supply missing engineering authority merely because it looks complete. Missing provenance stays visible without deleting the output. |
| Older drawing with a separately approved migration result | Show the existing owner's actual compatible/converted/partial/unavailable state and any receipt where available. CDDESIGN does not repeat migration, create a second backup sequence or silently undo C7's approved scoped behavior. Merely opening this document review grants no additional migration authority. |
| Newer unsupported CE data in an older version | Keep incompatible CE writes unavailable under CV8-11 while ordinary AutoCAD drafting remains available. Do not downgrade unknown records or treat unreadable data as an empty job to initialise over. |
| Report contradicts a retained manual value | Compare the candidate with that value and its basis; allow the existing confirmed value to remain while reviewing. Only an accepted governing change affects the relevant dependent results. |

The first useful action is to inspect the relevant current requirement or discrepancy, not to recreate every pit or redraw every catchment. For example, a partially drafted job may retain a confirmed manual catchment area while a newly selected report proposes another figure; existing geometry and schedule remain, their basis is shown, and the engineer reviews that one difference. A loose area note elsewhere is not silently merged into that confirmed record.

**Three-way existing-value comparison:** where a qualified relationship or explicit selection identifies relevant evidence, show the CE engineering record, any schedule-only override, and a loose drawing label separately. A matching displayed pit number or text value does not establish that relationship. The proposed first review offers Show on plan / Inspect record and preserves the current CE manual value, schedule override and unlinked label until a deliberate owner-supported action is reviewed. There is no newest-text winner, silent Refresh or automatic label adoption. A schedule-only override remains presentation, not a replacement engineering value; a loose label remains a drawing observation. If the engineer deliberately proposes its content as a manual fact or correction, use the existing owner review with exact target, source and scope—do not create a second CDDESIGN write path. Cancel of this comparison leaves all three existing states intact.

Closing without adoption preserves the pre-existing drawing and governing records, subject to separately completed owner actions already identified. It must not be described as rolling back a migration or earlier drawing edit. Future qualification starts with a mixed supported/legacy synthetic drawing and verifies exact retained records and candidate-only evidence, rather than assuming the job was empty.

## Selection is different from replacement or file deletion

- **Load document** adds it to the review set; extraction may propose facts but does not adopt them.
- **Remove from loaded set** unloads review material; it does not delete the original file or silently erase previously adopted evidence. If adopted facts refer to it, show that relationship and resulting access/currentness limitation before confirming the unload. Retained prior basis remains labelled, never falsely freshly verified.
- **Replace governing source** is a separate reviewed adoption: show changed facts, manual/pinned values, relevant consumers and source versions. It cannot be performed by merely ticking another PDF.
- **Keep current** leaves the adopted basis intact and the candidate available for later review. A pending report question is not a reason to stop all design work.

The file-picker purpose, if invoked through Select/change documents, is selecting documents for the recognised job. It is not an alternate project-root picker. Ambiguous/no project identity remains the existing open recovery choice; do not fabricate a job from whichever report was clicked.

## Competing versions and conflicts

| Evidence condition | Proposed review | What must not happen |
|---|---|---|
| Same report, later revision discovered | Show prior adopted and candidate revision with affected requirements highlighted. Preserve manual overrides beside the comparison. | No automatic adoption or all-job numerical invalidation from discovery alone. |
| Filename revision disagrees with title page | Show both facts and uncertainty; allow review of the actual page. | Never rewrite the report revision from filename alone. |
| Two reports give different values for the same purpose | Show the two citations plus current adopted basis and applicable precedence. Identify conflicting scope/purpose before comparing numbers. | No average, largest/smallest choice or first-file default. |
| One file changes while its pages are being extracted | Associate the returned candidates with the exact read version; mark superseded/changed-source result for review. | No stale extraction presented as the new file's evidence. |
| Source deleted/unavailable after adoption | Show Missing/Unavailable evidence and retained adopted identity. Qualify whether current use can be supported; do not invent a replacement. | Do not quietly zero the requirement, erase manual work or substitute a similar file. |
| Report has tables, scanned pages or inconsistent units | Show extracted item in context with its uncertainty and units. Manual transcription stays available with page evidence. | OCR confidence is not engineering approval; ambiguous digits do not become confirmed values. |

No external processing is implied by automatic extraction. Any provider use remains within already approved data destinations/permissions; an unavailable provider is not permission to switch services or upload the job folder. Proposed local discovery is distinct from the separately governed drawing-intelligence corpus programme.

## Changes while the review window is open

Switching to another recognised job uses that job's own shared context. The original pending source review remains tied to the original job; it is not retargeted. Returning restores the review if its source/version remains valid; otherwise show a new comparison while retaining pending manual input. A genuinely unknown job remains unresolved, not automatically Unassigned with a fabricated folder.

Cancel a page comparison: retain the working design and any pending input under its draft policy. Cancel extraction: show which document/page results are complete, pending or cancelled; a late result cannot adopt anything or reopen a closed review automatically. Closing CDDESIGN resolves actual pending design changes through its reviewed draft policy; it does not retract previously completed independent drawing operations.

## Synthetic planning checks

1. Open a new recognised job containing reports in Survey and Background: candidates found without a folder-link step; no design values adopted.
2. Tick a later report then close: loaded candidate changes, governing basis stays unchanged.
3. Untick an adopted report: original file remains; referenced design facts retain evidence identity and visible access status.
4. Conflicting pages specify different purposes: do not treat them as interchangeable numbers or choose a numerical winner.
5. Network folder fails halfway: show partial scope and retry only that discovery scope; keep completed relevant candidates and manual design work.
6. Change file/job during extraction: result remains source/version/job bound; no cross-job adoption.

These are proposed user journeys, not a live search, extraction, provider call or old-project test. Existing real-project evidence remains where the approved handover names it; no client corpus was accessed in this block.
