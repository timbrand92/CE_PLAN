## Technical detail (below the line, nothing Tim must act on)

1. **Structural isolation (new):** `Modules/Structural.Tests/TestIsolation/RealAppDataIsolationSetup.cs` is a `[SetUpFixture]` in the global namespace. Before the first test it creates `%TEMP%\ce-struc-test-run-<guid>\appdata`, sets `CE_STRUC_SUITE_APPDATA_ROOT` to it, and sets `CE_LOG_DIR_OVERRIDE` (honoured by the CE_SHARED files: admin telemetry tree, install salt, ribbon click log) to a sibling folder unless the runner already set it. After the last test it restores both and deletes the folder after checking the path is under temp and starts with the prefix. `SettingsServiceNoWriteTests` and `BeamCommandSettingsSnapshotReaderTests` save the value they find in `SetUp` and restore it in `TearDown`, so they now restore this set-up's folder; both pass (50 of 50 in the focused run).
2. **Guards:** `RealStructuralSettingsFileWatch` (Structural), `RealCivilSettingsFileWatch` (Civil, `TIM_CE_CADTOOLS\CD_Settings.json`), `RealManagerSwitchFileWatch` (Manager, `CE_SUITE\manager-switches.json`). Each reads `FileInfo` existence, length and last-write only; one pure test per project proves the comparison (created, deleted, longer, rewritten with the same length, untouched, never existed) and Structural has a test that the reader works while another handle holds the file exclusively.
