# BUGFIX w655 report, Mon 2 Nov 2026: BUG-1269 Cascade Preview shows plan warnings

## FOR TIM

1. **What you will see differently:** open Edit Pipe, Recalculate downstream inverts. The Cascade Preview window now lists the plan's warnings in orange-yellow text under the pipe and pit tables, BEFORE you press Apply. Example: a pit with two arriving pipes, the second 0.10 m lower, now shows "Pit PIT2: pipe P3 arrives at 98.40, lower than the 98.50 this change brings, so the pipe leaving the pit follows the lower level." Before, that line was worked out and thrown away, so you only found out after.
2. **What does not change:** the wording of every warning, the red errors list, the window size and Apply. A warning never stops Apply. Nothing is written to the drawing by the list, and nothing runs at U, UNDO or REDO.
3. **The off switch:** Settings key `preview.showsPlanWarnings`, ships ON. Set to false and the window is exactly as it was.
4. **My own mistakes first:** (a) I first put the new settings class between the window-feel class and its description, so the description sat on the wrong class. I caught it before building and fixed it. (b) My first AutoCAD-data listing printed 71,000 lines and included autosave file names that carry job addresses; I redid it and the report names none of them. (c) Nothing else went wrong in the build.
5. **What is NOT proven:** nobody has looked at the window in AutoCAD. The colour, that no label is hidden, and the scroll bar on a long list are unchecked. The window code cannot be unit-tested, so its list is pinned by reading the window's source text.
6. **Where it is:** draft PR #1989 against `claude/rel-20261102a`, title B-161 (provisional). One commit. BUG-1269 stays open (never marked fixed).
7. **One thing to know about the check of your real files:** some files under your AutoCAD data folders changed while I worked (settings value history, logs, usage and machine notes, the Structural log). An AutoCAD session (acad.exe, started 9:28:56 am, before my test began) was running and loading the plugin. My test run used its own scratch folders and wrote nothing at all, even there.
