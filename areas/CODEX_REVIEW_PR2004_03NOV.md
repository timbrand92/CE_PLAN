# CODEX REVIEW — PR #2004 — B-185 / BUG-1018

1. **Verdict: FIX FIRST.** The next command can still report that the pipe-object enabler is missing after it has loaded. The retry is governed by elapsed time, not by a new command. This violates BUG-1018's next-command requirement for a quick command sequence or script.
2. **Exact location:** `Modules/Drainage/Services/NativeObjects/CeCvlObjectsBridge.cs:125–126` at reviewed tip `6dce9df9df6ea6fabd6473b52030e2761706e130` (`w1018-nocache-notloaded`). Priority P2. [Changed lines](https://github.com/timbrand92/CE_ACAD_PLUGIN/blob/6dce9df9df6ea6fabd6473b52030e2761706e130/Modules/Drainage/Services/NativeObjects/CeCvlObjectsBridge.cs#L125).
3. **What goes wrong:** first check finds no enabler. A script loads it and calls CDPIPEOBJ within 1,000 ms of that check. The bridge returns the cached false without asking the loaded enabler. `NativePipeObjectCommands.cs:49–52` then prints the same “needs the CE pipe object enabler” message and exits. This is a deterministic managed-code reproduction; the scripted AutoCAD sequence itself has not been run.
4. **Required correction:** ensure the first check after a new command or a successful enabler load can re-probe immediately. If keeping a throttle inside a command, do not let it suppress the first check in the next command. Preserve the existing switch-OFF behaviour. The bridge is protected by this brief: implementation is routed back to the author; this review does not edit it.
5. **Acceptance remains open.** No AutoCAD, accoreconsole, install or deployment was started. BUG-1018 remains OPEN. PR #2004 must remain draft until corrected and rechecked.
