## Findings for the builder

1. **P1 — Grade text is orphaned after ordinary drawing edits.** `Modules/Drainage/Commands/AgiCommand.Apply.cs:103` creates `staged.GradeLabelId`, but the following registration at lines 108-109 links only `staged.LabelId` (the PD tag). `Modules/Drainage/Commands/AgiCommand.GradeLabel.cs:96` appends ordinary MText without a persistent drain association. MOVE leaves the grade at the old position; COPY of the drain does not supply its grade; ERASE leaves the old grade visible. The author acknowledges this, but it cannot remain a deferred design question: `C:\CE_PLAN\decisions\2026-10-29_TIM_ANSWERS.md:782`, answer 194 in the 4 November batch, explicitly says yes to moving, copying and erasing this text with its drain. BUG_CARPARK.md:11823 also requires a grade associated with the run. Add a separate grade attachment identity that cannot be overwritten by PD renumbering. Route any required LinkService/save/undo changes to their owner; this reviewer did not edit those protected files. Prove MOVE/COPY/ERASE, Undo/Redo, renumber and save/reopen, including locked and reference content.

2. **P2 — New label height and offset use millimetres as drawing units.** `Modules/Drainage/Commands/AgiCommand.GradeLabel.cs:83` passes `ConfiguredDrainTagTextHeight()` straight into the geometry builder; line 91 assigns that value to MText.TextHeight. The source value is explicitly `DrainTagTextHeightMm`, resolved without unit conversion at `AgiCommand.Apply.cs:179`. With INSUNITS=6 (metres), the default 250 mm becomes 250 drawing units = 250 m; line 70 also creates a 75 m gap, instead of 0.075 m. There is no millimetre-only admission check in this command's preflight. This is a new drawing-output defect, even though the old PD tag shares the same assumption. Convert the configured millimetres using the drawing's units before BOTH placement and height, and use the same conversion for readback. Existing `DrawingAreaUnits.MillimetresToDrawingUnits` demonstrates the repository conversion. Add an equivalent mm/metre case: height 250/0.25, gap 75/0.075, with the same physical result. The new tests only exercise height 250 in millimetre coordinates. This finding is source-and-unit arithmetic evidence, not an observed AutoCAD screenshot. The pre-existing grade calculation's millimetre assumption is separate and must not be described as introduced by this PR.

3. **P2 — No drafter-facing Settings switch.** `Modules/Drainage/Models/UserSettings.cs:3268` adds the JSON property and line 3269 defaults it ON. No changed Settings view, binding or view-model row exposes it; a repository search finds production references only in that model and the two command partials. The author's report explicitly confirms "No Settings page row". OFF works when the JSON is edited, but the stated Settings switch cannot be clicked. Add an ordinary existing-style row, verify save/reopen and both reader paths, and render/inspect its actual Settings page in dark and light. No new window design is needed.
