# w1095 report: X-Civil import uses the drawing's UNITS (BUG-505, decision 198) — 4 Nov 2026

## FOR TIM

1. **What you will see differently:** import an X-Civil drawing whose UNITS are set to Metres but whose objects look small. Before, CE guessed millimetres and brought the job in 1000 times too small, with only a "CHECK THE SCALE" warning. Now CE uses the Metres (multiplies by 1000) and the first pre-flight line says: "The source drawing's units are metres, so CE used them (multiplied by 1000) instead of the size guess." A drawing set to Millimetres that looks metre-sized now comes in at 1:1 with the matching line.
2. **Unchanged:** a drawing with UNITS not set, unreadable, or set to cm, inches or feet still uses the size guess and the old warnings (the "no units set; CE read it as millimetres" note included).
3. **Switch:** Settings, X-Civil import, `useSourceDrawingUnits`, ships on. Off = exactly the old behaviour.
4. **My own mistakes first:** (a) I first wrote the wrong bug number (BUG-1280, invented) in the files; I caught it before committing and it is BUG-505 everywhere. (b) My first test script had broken file paths and a missing `dotnet` path: two wasted runs, no harm.
5. **NOT proven:** nobody has opened this in AutoCAD. It is built and unit-tested only. The review-page banner of draft #1926 has not been run with this PR.
6. **Draft PR:** #2020, title B-206 (provisional), against `claude/rel-20261102a`.
7. **Robot case (to write, CE 02):** name it `N_xc_units` in the style of N31_dp_time. ## Technical detail

1. **Fault confirmed on `claude/rel-20261102a` (3fbb9da5):** `XcivilImportService.cs:325-332` takes the scale from `DetermineXcivilSourceToTargetScale` (size guess) and reads INSUNITS only to build the BUG-505 warning (`XcivilSourceUnitsCheck.Evaluate`). Units never decide the scale. Not already fixed. Civil, so not Structural-only. No window change needed, so no Codex brief.
2. **Carpark / decisions checked:** `BUG_CARPARK.md` BUG-505 (HUNT2-C-01); `decisions\2026-10-29_TIM_ANSWERS.md` item 198; `OPUS_PREREVIEW_BACKLOG2_R2_02NOV.md` (the #892 review). Decision 198 settles the question that review said was open.
3. **Change:** pure `XcivilSourceUnitsCheck.ResolveScale(guess, insunits, switchOn)`: INSUNITS 4 gives 1, 6 gives 1000, anything else (0, -1, other units) keeps the guess, switch off returns the guess. `UnitsUsedNote` gives the one plain line when the scale changed. In `XcivilImportService.cs` the INSUNITS read (already there, one open of the source) moved before the scale is fixed. Note order: units-used line, else the old CHECK THE SCALE, else the BUG-505 no-units note. The `[SCALE]` debug line now also shows the size guess.
4. **Switch:** `xcivilImport.useSourceDrawingUnits` (`XcivilImportSettings.UseSourceDrawingUnits`, `UserSettings.cs`), default true, doc ends "Default: on.". Read as `SettingsService.Current?.XcivilImport?.UseSourceDrawingUnits ?? true`. OFF: scale equals the guess, the Evaluate warning returns exactly (pinned in test).
