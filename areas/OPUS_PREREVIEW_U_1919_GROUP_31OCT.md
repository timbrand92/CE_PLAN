## DETAIL

### PR #1919, B-093: Grade mismatch window becomes one warning line

1. **What changes for the drafter.** At Draw, `Commands/CdCommand.cs` 586-595 writes one line, `[CE] Levels typed give 1 in 200, flatter than the 1 in 100 grade chosen. Your levels are used.` The Grade mismatch window is then skipped by `&& !gradeMismatchIsLine` at line 592. The same line shows in the New Pipe window's existing warning box (`ViewModels/CdViewModel.Inverts.cs` 689-716, through `CdDialog.xaml` 936-943). The window box and the command line both go through one decision, `EvaluateGradeMismatchWarning` (`CdCommand.Grade.cs` 236-265), which follows design rule 1. Steeper levels get "steeper than" (`Rules/GradeMismatchWarningRule.cs` 383, 406). Default grade with two typed levels flatter than `grade.defaultMinimumValue` gets "... minimum grade" (`CdCommand.Grade.cs` 254-261). CE's own suggested level is still never questioned (B-057, through `TryDetectCustomGradeMismatch`).
2. **Against Tim's ruling.** Item 118 ("1b"): the window is replaced and the levels are accepted. That matches. But the ruling says "strip and CDRULES", and CDRULES is not built. The PR says so (REGRESSION_LOG point 7), because the stored pipe does not hold the chosen grade. Item 119 ("2no but warn") is built as a guess, has its own switch, and is labelled UNCONFIRMED everywhere. Item 120 ("3yes") matches, and the minimum is read from Settings, not hard-coded.
3. **The grade label (main note).** In Custom mode `BuildGradeValue` (`CdCommand.Grade.cs` 194-202) labels the pipe with the Custom grade verbatim, whatever the levels say. The old window's default button was "Keep 1 IN 100" (`GradeMismatchDialog.xaml` 54-58, `IsDefault="True"`), so the new behaviour equals always pressing Enter. The "Use 1 IN 200" choice, which rewrote the label, is gone with the window. Result on a job: a pipe drawn 10.00 / 9.95 over 10 m is labelled 1 IN 100 while its levels give 1 in 200. Recommendation (no new behaviour, wording only): add "Label shows 1 IN 100." to the Flatter and Steeper lines in `GradeMismatchWarningRule.Line` (lines 403-408). Whether the label should follow the levels instead is Tim's engineering call. Do not decide it here.
4. **Smaller wording points.** (a) A first level read from a pit (draw-first), or levels refilled by Recall Last, are still called "Levels typed". (b) In Default Standard mode the figure is `defaultStandardValue`, but the line still calls it the "minimum". Neither one blocks the PR.
5. **Switches (R-00).** `pipe.gradeMismatchIsWarningLine`, `pipe.steeperThanGradeWarns`, `pipe.flatterThanMinimumWarnsInDefault`, all default ON (`Models/UserSettings.cs` 1490-1514), and each null-safe ON in the rule (`GradeMismatchWarningRule.cs` 367-373). All three are pinned through `DeserializeSettings` and `DeserializeSettingsTolerant`, and each typed false changes only itself (test lines 190-219). With the line switch OFF, the Custom path returns None (`CdCommand.Grade.cs` 248) and `gradeMismatchIsLine` is false, so the window opens exactly as before, including the BUG-857 Cancel. The Default-grade line has its own switch and is not part of "OFF restores old". That is correct, because Default grade never had a window. Hard-coded values: only a 1e-6 rounding allowance. The 10 percent is the existing Settings value.
6. **No hard blocks (R-27).** It removes a modal window and adds nothing that stops. The window's Cancel only comes back with the switch OFF, and that is the old path.
7. **Native protection and REDO.** It only adds `ed.WriteMessage` and a log line. No entity, layer, Xref, REFEDIT, regen, view or system variable is touched. REDO-safe.
8. **Tests.** `B093GradeMismatchWarningTests` calls the real decision method and the real view model. All of it would fail before (the method did not exist), and the expected text is the actual sentence. Gaps: (a) nothing proves that Draw skips the window (that needs AutoCAD). A one-line source guard for `&& !gradeMismatchIsLine` would be cheap. (b) The window box is not refreshed when the drafter clicks the Default or Standard grade button (the author's report says so too). Settings isolation: the assembly-wide `SettingsIsolationSetup.cs` sends every test to a temporary settings file, and the fixture restores the three switches in TearDown. Nothing touches %APPDATA%.
9. **Not proven.** The box and the command line on screen; that the window really stays away; a cross-plan break pair (the window box uses `KnownPipeLengthMm` while Draw uses the pipe's own length, so the two could disagree on a half pipe).
10. **Robot (CE 02).** Reuse the GM pair on the new build. (a) GM1p: Custom 1 in 100, start from a pit, 18.000 / 17.900 over 10 m. Expect no window, a command-line line containing "1 in 200, flatter than the 1 in 100", and the label read back as 1 IN 100. (b) GM2r: 18.000 / 17.800. Expect a "steeper than" line and no window. (c) Default grade, empty ground, 18.000 / 17.900. Expect a line ending "minimum grade. Your levels are used." (d) Control: `pipe.gradeMismatchIsWarningLine` false before AutoCAD starts. Expect the window to open on (a). **Codex look:** the New Pipe warning box showing the line in dark theme, and whether it wraps.
11. **Verdict: KEEP-WITH-NOTE.** Notes: the label wording above, the open question on item 119, and CDRULES still to build. Train: Civil New Pipe area plus Settings smoke S1 (new switches only, no Settings-engine change).

### PR #1920, B-096: cover to the outside top of the pipe on every screen

1. **What changes for the drafter.** New `Rules/PitCoverToPipeTopRule.cs` 38-60 measures, for every pipe end that runs into the pit, ground to the outside top of the pipe, using CDRULES' own `PipeCoverToOutsideRule.Measure`, and keeps the shallowest. The wall comes from the Settings wall table. An Unknown wall is measured to the inside top and the line says so. This matches decision 127 ("10yes") and decision 136 ("7cdrules").
2. **Switch.** `checks.screensMeasureCoverToPipeTop`, default ON (`UserSettings.cs` 3695-3703). It is pinned through both start-up reads, and a missing group reads ON (test lines 33-52). 3. **No hard blocks.** It only reports. The Hub finding stays Info.
4. **Native protection and REDO.** Read-only. A source guard bans Transaction, Regen, SetSystemVariable, Editor and file writes in the new rule. REDO-safe.
5. **Minor notes (do not block).** (a) Pits still need a readable pit invert before they are checked at all (`CivilNetworkHealthService.cs` 246), so a pit with pipes but no invert is skipped as before. (b) Pit matching also accepts the same pit name (`PitCoverToPipeTopRule.cs` 49). In a drawing with two pits both called P1, a pipe at the other P1 could set the figure. Nothing touches %APPDATA%. The author's real-file listing shows no settings file changed. Usage and failure notes did change, most likely from AutoCAD runs at the same time, and that is not proven either way.
7. **Not proven.** The live Inspector row, the Hub window and the CDGRAPH report on screen.

8. **Robot (CE 02).** The author's `N95_recall_new_upstream`, `N95_recall_new_upstream_off` and the held-fall control are sound (expected 19.40, 18.95 and 19.35). Add a 1 in 200 case expecting 19.42.
