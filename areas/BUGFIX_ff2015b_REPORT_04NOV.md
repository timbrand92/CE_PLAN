# BUGFIX ff2015b: PR #2015 CIVIL-OFF-1 fix-first (4 Nov 2026)

Built and unit-tested only. Nobody has opened any of this in AutoCAD. No bug marked FIXED. No new PR.

## FOR TIM

1. **What a drafter will see differently:** in a drawing marked Civil OFF, the pit blocks are no longer swapped to the new PIT BLOCK 3 when the drawing opens, and no regen runs. Before this fix they still were, even though Civil was OFF.
2. **Every CE command now refuses in an OFF drawing**, not only the 37 that had a start check. CDSYNC, CDUPGRADE, CDREBUILD, CDTIDYLABELS, PITSCHEDULE and CDCHECK all stop with "Civil is OFF in this drawing" and name the command. Only CDDISCIPLINE (to turn Civil back on) and CDUPGRADEDRAWING still run.
3. **Mistakes of my own:** none that cost a run. One thing to know: `gh` and `dotnet` are not on the tool PATH here, so I called them by full path.
4. **NOT proven (needs AutoCAD):** (a) the refusal is placed where AutoCAD takes the drawing lock for a command. A command that never takes the drawing lock (a read-only one) will not be stopped by it; I could not check which CE commands those are without AutoCAD. (b) That the stop really cancels the command in AutoCAD 2027 is not seen; the same "refuse the lock" method is already used by the double-click fix (BUG-859/860). (c) The open-time swap skip is checked by unit test only.
5. **Robot case that would prove it:** `ff2015b_off_gate`. Open a drawing, type `CDDISCIPLINE` then `Off`, then type `CDSYNC`. Check the command line contains "Civil is OFF in this drawing" and "CDSYNC has not run", and that the drawing is not modified (DBMOD 0). Repeat with `PITSCHEDULE`. Then type `CDDISCIPLINE` then `Civil` and `CDSYNC` again: it runs. Switch-off control: set `options.civilOffPerDrawing` false before launch, open the same drawing: no OFF is read, CDSYNC runs as before. Open-time swap: a drawing saved with OLD `PIT BLOCK` and tagged OFF; open it and read the block table (`-INSERT ?`): PIT BLOCK is still there and no PIT BLOCK 3 was added.
