# BUGFIX w958 report, 3 Nov 2026 (B-184, BUG-958)

## FOR TIM

1. **Result:** one draft PR is open: **#2003**, "B-184 BUG-958: windows CE fits to the screen remember where they were left". Built and unit-tested only. Nobody has opened it in AutoCAD. BUG-958 stays OPEN.
2. **What a drafter will see differently:** with "Remember where windows were last left" ticked in Settings, Edit Pipe, Edit Pit, New Pit and CDS reopen where you dragged them. Before, they always popped up at CE's own centre. Only the position comes back, never the size, so the whole editor still fits on screen.
3. **Why it happened:** CE's own screen-fitting step marks those four windows as "placed by hand", and the remember feature was told to leave anything placed by hand alone. It was skipping CE's own windows.
4. **The new switch:** Settings key `windowPlacement.rememberFittedWindows`, **on by default**. Switch it off and those four windows open at CE's centre exactly as before. It does nothing while "Remember where windows were last left" itself is off (that is still off by default, as Tim decided under INT-073).
5. **Mistakes of my own:** one. My first find-and-replace also rewrote the line inside the new helper, which would have made it call itself forever. I caught it on re-reading the file, before any build. No cost.
6. **BUG-959 is NOT in this PR.** It is a different fault (Civil Hub and the sizing code judge a saved position against the primary screen only). It sits in other code (`CivilHubDialog.xaml.cs` 419 to 467, `WindowSizingService.cs` `ApplyPreferredWindowSize` and `FitEditorWindow`, both still read `SystemParameters.WorkArea` on the base). The fix needs a monitor-by-monitor rewrite that cannot be proved without a second monitor, so it is not "the same small change". Still OPEN, no brief written yet.
7. **What is NOT proven:** (a) that the four windows really reopen at the dragged spot in AutoCAD; (b) behaviour on a second monitor or after a laptop is undocked; (c) that CDS (the Settings window) takes this path in the real app. I read that it uses the same fit (`TryFitTabbedEditor`), but I did not open it.
8. **Robot case that would prove it, with a switch-off control:** `W958_remember_fitted_window` (not written, no runner time used). It would: (1) set `windowPlacement.remember` ON and `rememberFittedWindows` ON before launch (CE reads settings at AutoCAD start); (2) open Edit Pipe on a pipe, read the window's left and top, move the window about 300 pixels right and down, close it with OK; (3) open Edit Pipe again and check left and top equal the moved spot within 2 pixels, and the width and height equal the first opening. Control: repeat with `rememberFittedWindows` OFF before launch and check the window opens at the first centred spot, not the moved one. The same steps for Edit Pit and New Pit. The robot can read window position from the window itself, so this needs no picture; Codex only if Tim wants the look checked.
